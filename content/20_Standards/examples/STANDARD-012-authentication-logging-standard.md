## Area

This standard defines the required events, fields, and retention requirements for logs generated by authentication and session management systems. It applies to all services that perform authentication, issue tokens, manage sessions, or handle credential verification. Logs governed by this standard are used for incident investigation, compliance reporting, and anomaly detection.

## Controls

- The following events must be logged: successful login, failed login attempt, account lockout, MFA challenge issued, MFA challenge passed, MFA challenge failed, token issued, token refreshed, token revoked, session created, session expired, session explicitly terminated, password changed, password reset initiated
- Each log entry must include: timestamp (ISO 8601 UTC), event type, user identifier or service account ID, source IP address, user agent (for browser flows), outcome (success/failure), and a correlation or request ID
- Sensitive values must never appear in logs: passwords, full token values, session secrets, or PII beyond a masked or hashed identifier
- Log entries must be written to an append-only, tamper-evident log store with access restricted to security and operations personnel
- Authentication logs must be retained for a minimum of 12 months in hot storage and 36 months in cold archive
- Failed authentication events exceeding 5 per account within 10 minutes must trigger an alert to the security monitoring system
- Log pipelines must have monitoring for gaps or anomalous drops in volume that could indicate logging failure
