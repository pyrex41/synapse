## Overview

The inventory service is a distributed platform responsible for maintaining accurate, real-time stock levels across all warehouses and fulfillment centers. It ingests stock movement events from multiple sources, calculates authoritative on-hand and available quantities per SKU per location, and exposes this data to downstream consumers including order management, merchant dashboards, and analytics pipelines.

This page was auto-generated by analyzing the inventory-service repository. See the individual system docs for operational details on each component.

## Key Components

The platform is composed of four primary services:

- **Warehouse Sync Gateway**: Receives and normalizes inbound stock events from external WMS providers via webhooks and polling adapters. Translates warehouse-native formats (EDI, proprietary JSON) into the platform's internal `StockEvent` schema.
- **Inventory Event Bus**: The central message broker. All stock movement events flow through this bus, ensuring durability and fan-out to multiple consumers with independent offsets and replay capability.
- **Stock Level Calculator**: Consumes events from the bus and maintains a continuously updated projection of on-hand, reserved, available, and in-transit quantities per SKU and location.
- **SKU Registry Service**: The master data store for product and SKU attributes. All other services resolve SKU identity through this registry.

## Architecture

The system uses an event-sourced architecture. Stock levels are derived projections computed by replaying the ordered sequence of stock movement events. This design provides a complete audit trail, enables point-in-time reconstruction, and decouples producers from consumers.

The data flow is:
1. Stock movement events enter via the Warehouse Sync Gateway (warehouse receipts, picks, transfers) or directly from the order management system (reservations, releases).
2. Events are validated, deduplicated, and published to the Inventory Event Bus.
3. The Stock Level Calculator consumes events and updates PostgreSQL projections.
4. Downstream systems query the Stock Level Calculator's REST API for current levels.

## Configuration

Key configuration parameters across the platform:

- **Event retention**: 90 days of event history in ScyllaDB (configurable per environment)
- **Reconciliation schedule**: Nightly warehouse-vs-platform variance check at 02:00 UTC
- **Cache TTLs**: Stock level query cache 5s; barcode resolution cache 60s
- **Sync polling intervals**: Per-warehouse, configurable from 1 minute to 24 hours
