## Overview

The `stock-level-calculation` repository implements the core algorithm used by the Stock Level Calculator service to maintain accurate inventory quantity projections. Stock levels are not stored directly — they are derived by accumulating an ordered sequence of stock movement events against a base snapshot. This event-sourced approach ensures full auditability and supports point-in-time reconstruction.

This page was auto-generated by analyzing the stock-level-calculation repository structure and key source files. Manual review is recommended for accuracy.

## Core Algorithm

The fundamental calculation is:

```
available_qty = on_hand_qty - reserved_qty
on_hand_qty   = snapshot_qty + SUM(delta for all committed movements since snapshot)
reserved_qty  = SUM(quantity for all open reservations)
```

Movement events carry a signed `delta` field: positive for inbound movements (receipts, returns) and negative for outbound movements (picks, transfers out). The engine applies deltas in strict `sequence_number` order per `(sku_id, location_id)` partition to prevent out-of-order corruption.

## Key Packages

### `internal/consumer`

RabbitMQ consumer that subscribes to stock movement topics. Each message is:
- Validated against the `StockMovementEvent` schema
- Checked for duplicate processing using the `idempotency_key` field
- Dispatched to the calculation engine worker for the appropriate partition

Partition assignment ensures a single worker processes all events for a given `(sku_id, location_id)` combination, eliminating concurrent write races without requiring distributed locks.

### `internal/engine`

The calculation engine applies movement deltas to the current stock level projection:

1. Read current projection row with `SELECT FOR UPDATE` to acquire a row-level lock
2. Verify the incoming event's `sequence_number` is exactly `last_sequence + 1`; if not, trigger reordering logic
3. Apply the signed `delta` to `on_hand_qty`
4. Update `reserved_qty` for reservation and release events
5. Recompute `available_qty = on_hand_qty - reserved_qty`
6. Write updated projection and mark event as processed within the same transaction

### `internal/snapshot`

Periodic snapshot writer that captures the current projection state as a base snapshot. Snapshots reduce replay time during service restarts. The snapshotting interval is configurable (default: every 1,000 events per partition).

### `internal/reconciliation`

Scheduled reconciliation worker that compares platform-computed stock levels against warehouse-reported physical counts. Raises discrepancy alerts when absolute variance exceeds `RECONCILIATION_THRESHOLD_PCT` (default: 0.5%).
